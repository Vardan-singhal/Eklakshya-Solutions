# MongoDB environment and Vercel deployment

## Environment files

- `.env`: ignored local settings. Enter your own `MONGODB_URI`; never upload this file.
- `.env.example`: safe tracked template with no real credentials.
- `src/lib/env.server.ts`: runtime-only private configuration validation.
- `src/lib/env.public.ts`: public site origin only.

Next.js and the seed script load root `.env`. Existing shell/Vercel variables take precedence.
Previous PostgreSQL configuration is unused; other existing credentials are preserved.

| Variable | Requirement |
| --- | --- |
| `MONGODB_URI` | Required for database-backed requests and seeding; Atlas or self-hosted URI |
| `MONGODB_DB` | Optional override; otherwise URI database, otherwise `eklakshya_solutions` |
| `MONGODB_DNS_SERVERS` | Optional comma-separated DNS IPs if SRV/TXT lookups fail; leave unset when system DNS works |
| `ADMIN_PASSWORD` | Optional; empty disables admin; at least 8 characters when set |
| `RAZORPAY_KEY_ID` and `RAZORPAY_KEY_SECRET` | Set both for online payments; leave both empty for manual bookings |
| `RAZORPAY_WEBHOOK_SECRET` | Required to accept Razorpay webhooks |
| `NEXT_PUBLIC_SITE_URL` | Public canonical origin set before build; defaults to https://eklakshya.com |

Only intentionally public values use `NEXT_PUBLIC_`. The Razorpay key ID is intentionally
returned to checkout, while private keys, MongoDB URI, webhook secret and admin password stay
on the server. There is no SMTP implementation or additional SMTP configuration.

## Local setup

1. Enter your actual MongoDB URI in `.env`. Use your existing MongoDB deployment or create one
   in Atlas. Configure its database user and network access for your application.
2. Include the intended database name in the URI or set `MONGODB_DB`.
3. Run:

```powershell
npm install
npm run db:check
npm run db:seed
npm run dev
```

Indexes initialize automatically before the first database operation. Your database user
must have permission to create indexes and read/write application collections. No real
credentials are generated by this project.

## Vercel

1. Open **Project Settings > Environment Variables**.
2. Add `MONGODB_URI` and, if needed, `MONGODB_DB`, plus the existing optional settings above.
3. Select **Production** for production credentials. Use separate databases/test payment keys
   for **Preview** and **Development**.
4. Keep the **Next.js** preset, repository root, `npm run build`, and default output directory.
5. Commit/upload the source and `.env.example`, with the updated `package.json` and
   `package-lock.json`. Remove obsolete Drizzle configuration from the repository.
   Never upload `.env`. Create a new deployment after changing dashboard variables.
6. Seed the intended database separately; builds do not seed, migrate or require a connection.

Razorpay, if enabled, retains its existing webhook route:
`https://YOUR_DEPLOYED_ORIGIN/api/payments/webhook`.

## Preserved behavior

The database swap changes content reads, seeding, admin queries and operational writes only.
Contact information, UI, animations, navigation, forms, rate limits, authentication and payment
signature verification remain intact. Atomic counters retain numeric booking references.
Compound/partial unique indexes retain duplicate-slot and gateway-order protections.

The public site builds without a configured database and retains its bundled-content fallback.
Missing configuration produces safe HTTP 503 responses when database features are requested.
Invalid form submissions remain 400; duplicate consultation slots remain 409. Private error
details are not logged or returned.

## Verify

```powershell
npm test
npm run typecheck
npm run build
git diff --check
git check-ignore .env .env.local .env.production
```

Regression tests use mocked MongoDB transport; they do not contact your cluster. With your
real URI configured, check `/api/health`, seed content, submit a future consultation and
verify it in the admin inbox. Run real write checks against development/preview first.

The old PostgreSQL records are not automatically copied to MongoDB. Historical SQL migrations
remain in `drizzle/` as reference only. No Git commit, push, external database mutation or
Vercel deployment is performed as part of the code change.
